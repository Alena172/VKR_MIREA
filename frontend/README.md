# Клиентское приложение

## Обзор

Клиентское приложение представляет собой одностраничное приложение на React + Vite, через которое пользователь проходит основной учебный цикл:

- регистрируется или входит
- переводит слова и фразы
- сохраняет элементы в словарь
- тренируется на сгенерированных упражнениях
- повторяет слова, срок повторения которых наступил, и слова с недавними ошибками
- просматривает историю сессий

Это основной пользовательский клиент API серверной части.

## Стек

- React
- Vite
- Tailwind CSS
- React Router

## Локальная разработка

```bash
cd frontend
copy .env.example .env
npm install
npm run dev
```

Стандартный адрес сервера разработки:

- `http://localhost:5173`

Ожидаемый API серверной части:

- `http://localhost:8000/api/v1`

## Переменные окружения

Клиентское приложение использует:

- `VITE_API_BASE_URL`: прямой адрес API
- `VITE_DEV_PROXY_TARGET`: дополнительная цель прокси для Vite в режиме разработки

См. [`.env.example`](d:\VKR\VKR_V3_Curs\frontend\.env.example).

## Основные экраны

### Главный экран и перевод

Главный экран является точкой входа для:

- аутентификации
- запросов на перевод
- сохранения слов в словарь

Этот поток тесно связан прежде всего с модулем `vocabulary`, внутри которого находятся подмодули `translation` и `base_lexicon`.

### Словарь

Экран словаря показывает уже сохраненные пользователем элементы.

Для каждого элемента ожидается `context_definition`, соответствующее исходному контексту. На стороне серверной части это определение строится по модели: сначала переиспользовать готовое определение, затем при необходимости обратиться к LLM.

### Тренировка

Тренировочный поток построен вокруг упражнений, которые генерирует сервер.

Важные особенности:

- генерация упражнений может быть асинхронной
- клиентское приложение запрашивает статус задачи, если серверная часть возвращает фоновую задачу
- ответы отправляются в API учебной сессии
- пользовательский интерфейс показывает поясняющие заметки, которые вернула серверная часть

Именно здесь пользователь сильнее всего ощущает AI-генерацию и семантическую проверку ответов.

### Повторение

Экран повторения ориентирован на уже известные слова и помогает выбрать, что повторять сейчас.

Он объединяет:

- слова, срок повторения которых наступил
- недавние ошибки
- дополнительные смысловые сигналы от `learning_graph`

То есть рекомендации здесь отвечают в первую очередь на вопрос "что повторять сейчас".

### История сессий

Экран истории показывает прошлые учебные сессии, детали ответов и серверные фильтры, например по дате и точности.

## Аутентификация и токены

Одностраничное приложение работает через JWT-аутентификацию серверной части.

Текущие детали реализации:

- JWT хранится в хранилище браузера
- авторизованные запросы отправляют bearer-токен
- приложение использует проверки вроде `/auth/verify` и `/auth/me` для восстановления состояния сессии

Для текущего этапа это приемлемо, но это скорее практическая деталь реализации, чем целевая долгосрочная модель безопасности.

## Зависимости от серверной части

Клиентское приложение зависит от следующих возможностей серверной части:

- identity
- vocabulary
- learning
- learning_graph
- infrastructure/tasks

Если серверная часть или рабочий процесс фоновых задач недоступны, это быстрее всего проявится в генерации упражнений, обновлении потока повторения и сценариях перевода.

## Замечания по текущим границам продукта

Текущее состояние клиентского приложения честно отражает текущий продукт:

- самый сильный пользовательский путь сейчас: перевод, сохранение в словарь, тренировка, повторение
- сценарий повторения заметно зрелее, чем гипотетическая система глобальной рекомендации новых слов
- `learning_graph` показывается как улучшающий слой вокруг интересов пользователя и смыслов слов

## Полный запуск всех компонентов

Из корня репозитория:

```bash
docker compose up -d --build
```

Типичные локальные адреса:

- клиентское приложение: `http://localhost:5173`
- API серверной части: `http://localhost:8000`
