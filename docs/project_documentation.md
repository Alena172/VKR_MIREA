# Документация проекта

## Назначение проекта

Проект представляет собой платформу для персонализированного изучения английской лексики русскоязычными пользователями. Основная идея системы - связать новое слово с реальным контекстом, сохранить его в личный словарь, сформировать упражнения и затем возвращать слово в повторение по мере необходимости.

Платформа поддерживает полный учебный цикл:

1. пользователь вводит или захватывает слово из текста;
2. система получает перевод и контекстное определение;
3. слово сохраняется в персональный словарь;
4. пользователь проходит упражнения;
5. система оценивает ответы и обновляет прогресс;
6. слова попадают в очередь повторения через SRS.

## Состав системы

```text
frontend/   Веб-приложение React для основного учебного сценария.
backend/    FastAPI-сервер, бизнес-логика, БД, миграции и фоновые задачи.
extension/  Браузерное расширение для быстрого захвата слов со страниц.
gateway/    Nginx-конфигурация для единой локальной точки входа.
docs/       Архитектурные, предметные и справочные материалы.
```

## Основные компоненты

### Backend

Серверная часть реализована на FastAPI и построена как модульный монолит. Приложение запускается как один сервис, но бизнес-логика разделена на модули:

- `identity`: пользователи, JWT-аутентификация, текущий пользователь;
- `vocabulary`: личный словарь, перевод, сохранение слова из контекста;
- `learning`: генерация упражнений, учебные сессии, проверка ответов, SRS;
- `learning_graph`: интересы пользователя, смыслы слов, семантические связи;
- `ai_services`: единая точка доступа к AI-провайдерам и локальным fallback-сценариям;
- `platform`: технические механизмы приложения, например статусы фоновых задач.

Внутри backend используются SQLAlchemy, Alembic, PostgreSQL, Redis и Celery.

### Frontend

Клиентское приложение реализовано на React + Vite. Оно предоставляет основные экраны продукта:

- вход или регистрация;
- перевод и сохранение слов;
- словарь пользователя;
- тренировка;
- повторение слов;
- история учебных сессий.

Frontend работает с backend через HTTP API и хранит JWT для авторизованных запросов.

### Browser Extension

Расширение помогает быстро перенести слово из веб-страницы в учебную систему. Пользователь выделяет текст, расширение отправляет его в backend, получает перевод и может сохранить результат в словарь.

Расширение является вспомогательным клиентом. Основное обучение происходит в веб-приложении.

### Infrastructure

Локальная инфраструктура поднимается через Docker Compose:

- PostgreSQL хранит пользователей, словарь, сессии, прогресс и семантические данные;
- Redis используется для Celery и очередей;
- Celery выполняет фоновые задачи, например генерацию упражнений;
- Flower показывает состояние фоновых задач;
- Nginx может использоваться как единая точка входа.

## Пользовательские сценарии

### Добавление слова

Пользователь вводит слово во frontend или захватывает его через расширение. Backend нормализует слово, получает перевод, подбирает или генерирует контекстное определение и сохраняет запись в `vocabulary_items`.

### Генерация упражнений

Пользователь запускает тренировку. Backend выбирает словарные элементы, формирует seed-данные и обращается к AI-сервису или fallback-логике. При тяжелой генерации задача может выполняться через Celery.

### Отправка сессии

После выполнения упражнений frontend отправляет ответы. Backend сохраняет учебную сессию, ответы пользователя, точность и пояснения. Эти данные затем используются в истории и повторении.

### Повторение

Модуль `learning` ведет прогресс по словам: количество ошибок, серию правильных ответов, дату последнего повторения и дату следующего повторения. На основе этих данных строится очередь SRS.

### Семантический профиль

Модуль `learning_graph` связывает слова с интересами пользователя и конкретными смыслами. Это помогает учитывать контекст, различать значения одной леммы и объяснять, почему слово связано с темой пользователя.

## Данные и база

Основные группы таблиц:

- пользователи и уровень CEFR;
- элементы словаря;
- учебные сессии и ответы;
- прогресс повторения слов;
- интересы, смыслы слов и семантические связи;
- базовый локальный лексикон.

Схема развивается через Alembic-миграции. Подробности доступны в `docs/database_schema.md` и `docs/database_schema.sql`.

## API

Основные группы API:

- `/api/v1/auth/*`: токены, вход, проверка текущего пользователя;
- `/api/v1/vocabulary/*`: словарь и сохранение слов;
- `/api/v1/translate/*`: перевод;
- `/api/v1/exercises/*`: генерация упражнений;
- `/api/v1/sessions/*`: учебные сессии;
- `/api/v1/context/*`: повторение и прогресс слов;
- `/api/v1/learning-graph/*`: интересы, смыслы и связи;
- `/api/v1/tasks/*`: статусы фоновых задач.

Актуальный список маршрутов удобнее смотреть в Swagger UI после запуска backend:

```text
http://localhost:8000/docs
```

## Локальный запуск

### Backend через uv

```bash
cd backend
uv sync
uv run alembic upgrade head
uv run uvicorn app.main:app --reload
```

Перед миграциями должен быть доступен PostgreSQL из `DATABASE_URL`.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

### Полный стек

```bash
docker compose up -d --build
```

Основные адреса:

- frontend: `http://localhost:5173`;
- backend: `http://localhost:8000`;
- gateway: `http://localhost:8080`;
- Flower: `http://localhost:5555`.

## Проверки

Для backend:

```bash
cd backend
uv run pytest -q
uv run python tools/check_module_boundaries.py
```

Для frontend:

```bash
cd frontend
npm run build
```

## Правила разработки

- Межмодульные обращения в backend должны идти через `public_api.py` или специализированные публичные фасады.
- SQLAlchemy-модели хранятся в слое `models`, репозитории отвечают за запросы к БД.
- HTTP-роутеры должны оставаться тонкими: принимать запрос, вызвать сервис или фасад, вернуть схему ответа.
- Тяжелые операции лучше выносить в Celery-задачи.
- Документацию нужно обновлять вместе с изменением пользовательского сценария, API или структуры модулей.
