# Документация проекта

## Назначение проекта

Проект представляет собой платформу для персонализированного изучения английской лексики русскоязычными пользователями. Основная идея системы — связать новое слово с реальным контекстом, сохранить его в личный словарь, сформировать упражнения и затем возвращать слово в повторение по мере необходимости.

Платформа поддерживает полный учебный цикл:

1. пользователь вводит или захватывает слово из текста;
2. система получает перевод и контекстное определение;
3. слово сохраняется в персональный словарь;
4. пользователь проходит упражнения;
5. система оценивает ответы и обновляет прогресс;
6. слова попадают в очередь повторения через SRS.

## Состав системы

```text
frontend/   Веб-приложение React для основного учебного сценария.
backend/    FastAPI-сервер, бизнес-логика, БД, миграции и фоновые задачи.
extension/  Браузерное расширение для быстрого захвата слов со страниц.
gateway/    Nginx-конфигурация для единой локальной точки входа.
docs/       Архитектурные, предметные и справочные материалы.
```

## Основные компоненты

### Backend

Серверная часть реализована на FastAPI и построена как модульный монолит. Приложение запускается как один сервис, но бизнес-логика разделена на шесть доменных модулей:

- `identity`: пользователи, JWT-аутентификация, текущий пользователь;
- `vocabulary`: общий словарь (`dictionary_entries`), личный словарь (`user_vocabulary`), перевод, захват слова из контекста, базовый лексикон;
- `training`: генерация упражнений, учебные сессии, проверка ответов, история;
- `review`: SRS-повторение, очередь повторения, план, сводка прогресса;
- `graph`: тематический профиль пользователя, интересы по кластерам, рекомендации новых слов;
- `ai`: единая точка доступа к AI-провайдерам, гибридный перевод, генерация упражнений, объяснение ошибок.

Внутри backend используются SQLAlchemy, Alembic, PostgreSQL, Redis и Celery.

### Frontend

Клиентское приложение реализовано на React + Vite. Оно предоставляет основные экраны продукта:

- вход или регистрация;
- перевод и сохранение слов;
- словарь пользователя;
- тренировка;
- повторение слов;
- история учебных сессий.

Frontend работает с backend через HTTP API и хранит JWT для авторизованных запросов.

### Browser Extension

Расширение помогает быстро перенести слово из веб-страницы в учебную систему. Пользователь выделяет текст, расширение отправляет его в backend, получает перевод и может сохранить результат в словарь.

Расширение является вспомогательным клиентом. Основное обучение происходит в веб-приложении.

### Infrastructure

Локальная инфраструктура поднимается через Docker Compose:

- PostgreSQL хранит пользователей, словарь, сессии, прогресс и семантические данные;
- Redis используется для Celery и очередей;
- Celery выполняет фоновые задачи, например генерацию упражнений и обработку захватов;
- Flower показывает состояние фоновых задач;
- Nginx может использоваться как единая точка входа.

## Пользовательские сценарии

### Добавление слова

Пользователь вводит слово во frontend или захватывает его через расширение. Backend нормализует слово, получает перевод из общего словаря (`dictionary_entries`) или через AI, подбирает или генерирует контекстное определение и сохраняет запись в `user_vocabulary`.

При повторном добавлении того же слова система переиспользует уже существующую запись из `dictionary_entries`: AI не вызывается, перевод берётся из общего словаря.

### Генерация упражнений

Пользователь запускает тренировку. Backend выбирает словарные элементы, формирует задания трёх типов:

- `sentence_translation_full` — перевод предложения с целевым словом;
- `word_scramble` — восстановление слова из перепутанных букв;
- `word_definition_match` — сопоставление слова с определением.

Тяжёлые задачи выполняются через Celery; при недоступности AI используется локальный fallback.

### Отправка сессии

После выполнения упражнений frontend отправляет ответы. Backend сохраняет учебную сессию, ответы пользователя, точность и пояснения. Эти данные затем используются в истории и повторении.

### Повторение

Модуль `review` ведёт прогресс по словам: количество ошибок, серию правильных ответов, дату последнего повторения и дату следующего повторения. На основе этих данных строится очередь SRS с шагами [1, 3, 7, 14, 30, 60] дней.

### Семантический профиль и рекомендации

При добавлении каждого слова модуль `graph` эвристически определяет его тему (technology, business, travel и др.) и накапливает вес интереса пользователя к этой теме в `user_interests`. На основе профиля интересов система рекомендует новые слова из общего словаря, которые относятся к тем же темам, но ещё не сохранены пользователем.

## Данные и база

Основные группы таблиц (7 таблиц):

- `users` — пользователи и уровень CEFR;
- `topic_clusters` — глобальные тематические кластеры (technology, business, travel и др.);
- `dictionary_entries` — общий словарь: лемма, перевод, контекстное определение, тема (`topic_cluster_id`);
- `user_vocabulary` — личный словарь: ссылка на `dictionary_entries` плюс исходное предложение и URL;
- `word_progress` — SRS-прогресс по словам (SM-2: ease_factor, interval_days);
- `learning_sessions`, `learning_session_answers` — учебные сессии и ответы;
- `user_interests` — веса интересов пользователя по тематическим кластерам.

Схема развивается через Alembic-миграции (22 версии). Подробности в `docs/database_schema.md`.

## API

Основные группы API (все маршруты под префиксом `/api/v1`):

| Префикс | Назначение |
|---|---|
| `/auth/*` | Токены, вход, проверка текущего пользователя |
| `/users/*` | CRUD пользователей |
| `/vocabulary/me`, `/vocabulary` | Личный словарь |
| `/translate/me` | Перевод с контекстом |
| `/exercises/me/generate` | Генерация упражнений (async) |
| `/sessions/*` | Учебные сессии и история |
| `/context/me/*` | Повторение, прогресс слов, очередь, план |
| `/learning-graph/me/*` | Интересы, смыслы, семантические связи |
| `/ai/explain-error`, `/ai/status` | AI-объяснение ошибок, статус провайдера |
| `/tasks/*` | Статусы фоновых задач |

Актуальный список маршрутов удобнее смотреть в Swagger UI после запуска backend:

```text
http://localhost:8000/docs
```

## Локальный запуск

### Backend через uv

```bash
cd backend
uv sync
uv run alembic upgrade head
uv run uvicorn app.main:app --reload
```

Перед миграциями должен быть доступен PostgreSQL из `DATABASE_URL`.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

### Полный стек

```bash
docker compose up -d --build
```

Основные адреса:

- frontend: `http://localhost:5173`;
- backend: `http://localhost:8000`;
- gateway: `http://localhost:8080`;
- Flower: `http://localhost:5555`.

## Проверки

Для backend:

```bash
cd backend
uv run pytest -q
```

Для frontend:

```bash
cd frontend
npm run build
```

## Правила разработки

- Межмодульные обращения в backend идут через сервисный слой: только `service/*.py` другого модуля, никогда не напрямую через `repository.py` или `models.py`.
- SQLAlchemy-модели хранятся в слое `models`, репозитории отвечают за запросы к БД.
- HTTP-роутеры должны оставаться тонкими: принять запрос, вызвать сервис или фасад, вернуть схему ответа.
- Тяжёлые операции выносятся в Celery-задачи; эндпоинты возвращают `202 Accepted` с `task_id`.
- Документацию нужно обновлять вместе с изменением пользовательского сценария, API или структуры модулей.
